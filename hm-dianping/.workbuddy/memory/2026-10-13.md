## 黑马点评：缓存击穿答疑 + CacheClient 代码 review

- 讲清了缓存击穿两方案区别：互斥锁不需要预热；逻辑过期必须预热（key 无真实 TTL，全靠预热写入，否则查无数据但不报错）。
- review 发现 4 个 bug（用户自己改，未代改）：
  1. `ShopServiceImpl.saveShopRedis` 写 key `"cach:shop"+id`（拼错+少冒号），与查询用的 `CACHE_SHOP_KEY="cache:shop:"` 不一致，预热白做；
  2. `CacheClient.queryWithPassMutex` 中 `lockkey = key`，锁和缓存同 key，setIfAbsent 永远 false → 永远不重建；应改用 `LOCK_SHOP_KEY`；
  3. finally 里立即 unlock，但重建是异步线程池任务，锁提前释放；标准写法是重建完成后再释放+二次检查缓存；
  4. `saveShopRedis` 中 shop==null 只 log 不 return，null 被写入 RedisData。
- 注意：用户把逻辑过期方法命名为 queryWithPassMutex（Mutex 是互斥锁的意思），提醒过名字歧义。
- 修复建议顺序：先改 Bug 1、2，删 Redis 脏 key，再跑 saveShopRedis 预热测试。
