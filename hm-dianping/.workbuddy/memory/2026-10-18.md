## ShopServiceImpl 缓存方法封装 review（只讲不改性）

用户要求以「10 年 Java 程序员」视角讲解 `ShopServiceImpl.queryByIDPenetration`（缓存穿透方案：空值缓存）的封装思路，明确不改代码。

发现的问题（已口头指出，未落地修改）：
1. **致命**：方法末尾 `return shop;` 应为 `return shopUser;` —— 缓存未命中走 DB 查到值后，写进 Redis 的是 `shopUser`，返回的却是 `shop`（由 null 解析而来 = null）。4 条 return 路径有 3 条返回 null。
2. `JSONUtil.toBean(shopJson, Shop.class)` 写在 `StrUtil.isNotBlank` 判断之前，缓存未命中时 shopJson 为 null，白干活且版本相关地可能抛异常。
3. 命中空串标记分支 `return shop` 语义丢失，调用方无法区分「null」和「不存在」。
4. 方法未声明进 `IShopService` 接口、无 `@Override`。
5. `CacheClient` 目前是空壳（只有一个类的骨架），泛型方法尚未实现。

讲的封装思路：
- 用 `CacheClient` + 泛型 `<R, ID>` + `Function<ID, R> dbFallback` + `Class<R> type` 做行为参数化，把「查哪个库/哪个表」当参数传进来（方法引用 `this::getById`）。
- 因泛型擦除，必须显式传 `Class<R>` 才能反序列化。
- 工具类返回实体而非 `Result`，由 Service/Controller 决定包装 —— 用户把返回类型从 Result 改成 Shop 这一步方向正确。
- 顺带厘清 穿透 / 击穿 / 雪崩 三者区别与对应解法。
