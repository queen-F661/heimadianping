## 排错：BlogServiceImpl 点赞报 WRONGTYPE

- 报错：`WRONGTYPE Operation against a key holding the wrong kind of value`，栈顶在
  `BlogServiceImpl.isBlogLiked` 第 92 行 `opsForZSet().score(...)`，由 `/blog/{id}` 触发。
- 根因（已连 Redis 192.168.45.128:6379 实证）：`blog:licked:5/7/55/4/6` 这几个 key 在 Redis 里是
  **set** 类型（老版 Set 点赞实现留下的脏数据，`SMEMBERS blog:licked:7` = {1010}），
  而现在的代码用 ZSet 命令去读，类型不匹配 → 直接抛异常。
- 已处理：`DEL` 掉这 5 个 set 类型脏 key，`KEYS blog:licked:*` 现为空。
- 待用户自行修改的代码问题：
  1. `BlogServiceImpl` 第 90、100 行 key 硬编码 `"blog:licked:"`（拼错），
     与 `RedisConstants.BLOG_LIKED_KEY = "blog:liked:"` 不一致，
     导致 `queryBlogLikes()` 永远查不到点赞数据，应统一改用常量。
  2. `isBlogLiked` 里 `UserHolder.getUser().getId()` 先解引用再判 null，属反条件分支，未登录会 NPE。
  3. `queryBlogLikes` 的 `range(key, 0, 5)` 是闭区间取 6 条（应为 0,4），且方法末尾 `Result.ok()` 未带数据。
- 教训：key 前缀统一走 RedisConstants 常量；换数据结构（Set→ZSet）时老 key 必须清，
  否则同名不同类型的 key 会以 WRONGTYPE 形式爆出来。
