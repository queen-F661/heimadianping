## CacheClient / setWithLogicalExpire 教学 + 代码 review
- 用户已实现 `CacheClient.java`（set / setWithLogicalExpir / queryWithPassThrough / queryWithPassMutex）。
- 讲解逻辑过期原理：key 不设 TTL，过期时间塞进 RedisData.value，代码判断，过期后抢锁 + 异步线程重建，主线程返回旧数据。
- 指出的 bug（用户自己改，未代写）：
  1. 方法名拼错 `setWithLogicalExpir` → `setWithLogicalExpire`。
  2. `unit` 参数未使用，`plusSeconds(time)` 把任何单位当秒，应 `plusSeconds(unit.toSeconds(time))`。
  3. 严重：`queryWithPassMutex` 里 `lockkey = key`（锁 key = 缓存 key），key 已存在导致 setIfAbsent 永远 false，重建线程永远不执行；应 `LOCK_SHOP_KEY + id`。
  4. 命名误导：`queryWithPassMutex` 实际是逻辑过期方案，建议改名 `queryWithLogicalExpire`；互斥锁方案是另一个（拿不到锁 sleep 重试）。
  5. `queryWithPassThrough` 里 `this.set(key,r,3L,TimeUnit.MINUTES)` 硬编码，没用传入的 time/unit。
