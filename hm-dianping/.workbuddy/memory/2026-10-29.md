## 黑马点评 关注+Feed 流（saveBlog / queryBlogOfFollow）

- 修 `BlogServiceImpl.saveBlog`：`eq("follower_id", ...)` 列名不存在 → 改成 `follow_user_id`。
  语义：tb_follow 里 `user_id` = 粉丝（箭尾），`follow_user_id` = 被关注者（箭头）。博主发笔记要按箭头终点反查粉丝。
- 修 `BlogServiceImpl.queryBlogOfFollow`：解析 Redis ZSet 的循环里漏了 `ids.add(...)`，
  导致 `id IN ()` / `ORDER BY FIELD(id,)` 语法错。同时把 `List<Object>` 改为 `List<Long>`，删掉未使用的 score 变量。
- 收件箱为空时不再返回 `Result.ok()`（data=null），改为返回空的 ScrollResult（list 空集合），保证前端结构统一。
- 修 `FollowServiceImpl.followCommons`：key01/key02 都用 `id`，导致求交集变成自己跟自己，key02 改为 `id1`。
- `saveBlog` 里 `"feed:"` 硬编码换成 `FEED_KEY` 常量，变量 `userId` 改名 `fanId` 避免和博主 id 混淆。
- `saveBlog` 加入参校验：shopId/title/images/content 为空时直接 `Result.fail` 返回可读提示，
  取用户后补了 null 判断。原因：tb_blog 这几个字段 NOT NULL 且无默认值，MyBatis-Plus 插入策略
  NOT_NULL 会跳过 null 字段，导致 INSERT 里缺列 → `Field 'xxx' doesn't have a default value`。
  发笔记必须从店铺详情页进入（URL 带 shopId），否则前端不会传 shopId。
