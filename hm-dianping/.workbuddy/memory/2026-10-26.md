- 现象：用户在 redis-cli 执行 `XGROUP DESTROY stream.order g1` 报 `ERR ... requires the key to exist`，换成 `stream.orders` 后返回 `(integer) 1`。

  - `src/main/resources/seckill.lua:37` → `XADD stream.orders *`

## 追加：NOGROUP 报错（同日 22:03）

- 报错：`io.lettuce.core.RedisCommandExecutionException: NOGROUP No such key 'stream.orders' or consumer group 'g1' in XREADGROUP with GROUP option`
- 根因：上一轮 `XGROUP DESTROY stream.orders g1` 删组后**没有重建**，应用启动时 Handler 线程立即 XREADGROUP → 组不存在。属于上一步操作的直接后果，不是新 bug。
- 关键认知：Stream 消费者组**不会自动创建**（没有 Kafka 的 auto-create）；`XADD` 只创建 stream 不创建组，两层是分开的。
- **已验证的版本限制**：该项目 `spring-data-redis 2.6.2`（pom 里显式锁了版本，覆盖 Boot 2.3.12 的默认 2.3.x），用 `javap` 查 `StreamOperations` 只有：
  - `createGroup(K, String)`
  - `createGroup(K, ReadOffset, String)`
  - **没有 mkStream 重载**，所以 key 不存在时 createGroup 会直接失败。要 MKSTREAM 只能走 `RedisCallback` 手动发原生命令。
- 推荐做法：`queueName` 从内部类 `VoucherOrderHandler` 提为外部类 `static final` 常量，在 `@PostConstruct init()` 里建组，并吞掉 BUSYGROUP。
- 项目版本备忘：Boot 2.3.12.RELEASE + spring-data-redis 2.6.2 + lettuce 6.1.6 + redisson 3.13.6 + mybatis-plus 3.4.3 + Java 8。

## 追加：首页分类图标空白（/shop-type/list 不返回）

- 顺带确认：`UserServiceImpl.login` 写 `"login:user:" + token`，`RefreshTokenInterceptor`/`LoginInterceptor` 读同一 key，三者一致，登录态链路本身没问题。

## 追加：Stream 教学 + 产出笔记（23:00-23:30）

用户要求一步步讲 Stream 消费逻辑，采用"全景图 → 概念 → 写侧 → 读侧 → 五行走读 → 双循环 → ACK 铁律"的顺序，中途多次用自己的话复述，纠正了这些概念：

- `list.get(0)` 的 0 是**集合下标**不是消息 ID；`count(1)` 与 `get(0)` 是契约
- Lua 传的 3 个参数是**打包成 1 条消息**（含 3 个字段），不是 3 个独立元素
- `fillBeanWithMap` 是"填进去 + 返回同一对象"，必须接返回值；填的是**对象**不是类
- ACK 删的是 pending 里的**登记记录**，不删消息本体（XLEN 不变）
- ACK 必须在落库**之后**（at-least-once），反了会永久丢单
- 补偿分支是 `while` 循环直到捞空才 `break`，不是查一次
- 用 `XRANGE - +` 不能消费：不产生 pending，ACK 无从谈起
- `count` 调大只是省 Redis 往返，处理仍串行，提吞吐要靠加消费者
