## 店铺详情页「代金券」区域空白 排查结论

**现象**：tb_voucher 里有券（id=52 → shop_id=2，id=53 → shop_id=8，status=1），但店铺详情页代金券区空白。

**验证过程**：后端跑在 8081。带 Redis token（login:user:<uuid>）实测：
- `GET /voucher/list/8` → 正常返回 id=53 的券
- `GET /voucher/list/2` → 正常返回 id=52 的券
- `GET /voucher/list/9` → `{"success":true,"data":[]}` 空
- 不带 token → 全部 401

**结论**：接口和 SQL 没问题。两个原因：
1. 页面打开的是 shop id=9（羊老三羊蝎子…运河上街店），这家店库里没券。有券的是 2 和 8 号店。
2. `MvcConfig` 的 `excludePathPatterns` 缺 `/voucher/**`，未登录访问直接被 LoginInterceptor 拦成 401 → 前端拿不到数据同样空白。原版黑马需要放行 /shop/**、/voucher/**、/shop-type/**、/upload/**、/blog/hot、/user/code、/user/login。

**顺带确认**：
- 代金券不走 Redis 缓存（cache:shop:{id} 只存店铺字段），Redis 里没券属正常。
- tb_seckill_voucher 里 52/53 的 end_time = 2026-10-18 12:09:04，已过期，点抢购会失败，需改时间。
- VoucherMapper.xml 查询带 `v.status = 1`，手动插数据要保证 status=1。

## 追加：第二轮（用户新建 id=55 券后仍不显示）

用户自己加了 tb_voucher id=55 / shop_id=9，并把 `/voucher/**` 放进了 MvcConfig 的放行列表（401 已解决，接口无 token 也返回 200）。

**真正根因**：前端 `shop-detail.html` 第 67 行
`<div class="voucher-box" v-for="v in vouchers" :key="v.id" v-if="!isEnd(v)">`
配合 `isEnd(v){ return new Date(v.endTime).getTime() < Date.now() }`——**过期券前端直接不渲染**。
id=55 的 begin_time 与 end_time 都被写成 `2026-10-21 23:09:17`，用户 23:11 打开页面，已过期 2 分钟 → 被过滤 → 空白。

**已处理**：`UPDATE tb_seckill_voucher SET begin_time='2026-10-21 00:00:00', end_time='2026-10-31 23:59:59' WHERE voucher_id=55;` 并 curl 验证 `/voucher/list/9` 返回 endTime 2026-10-31。

**隐藏坑记录**：
- 52/53 的 end_time 仍是 2026-10-18，早过期，看 2/8 号店同样空白。
- 普通券 type=0 且无 tb_seckill_voucher 记录时，LEFT JOIN 出来 endTime=null → `new Date(null)`=1970 → isEnd 恒 true，普通券永远不会显示。
- 前端 common.js 响应拦截器 `return response.data`（Result 对象），页面里 `({data}) => this.vouchers = data` 取的正是数组，逻辑没问题。
- `VoucherOrderServiceImpl.seckillVoucher` 目前是同步 DB 扣减版（lua 流程被注释掉），所以 Redis 没有 `seckill:stock:*` 不影响抢购；但 `UserHolder.getUser()` 为 null 会 NPE。

**第三次（2 号店）**：同一根因复发。id=52 的 end_time 仍是 2026-10-18 12:09:04（已过期 3 天），前端 isEnd 过滤 → 空白。
已执行 `UPDATE tb_seckill_voucher SET begin_time='2026-10-21 00:00:00', end_time='2026-10-31 23:59:59' WHERE voucher_id IN (52,53);`，52/53/55 三张券有效期统一到 10-31，curl 验证 /voucher/list/2 正常返回。
待办提醒：id=1（type=0，无 seckill 记录，endTime=null）永远不显示，需补 tb_seckill_voucher 记录或改前端 isEnd 兼容 null。
